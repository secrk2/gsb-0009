# 安运通 · 危货运输监管平台（骨架版）

省级危险货物道路运输监管平台重建项目。当前交付系统骨架与三个核心菜单：**运单作战台**、**运输排班**、**电子运单**（含完整状态机、企业数据隔离、离线容错）。

## 一键启动

```bash
docker compose up -d --build
```

| 入口 | 地址 | 说明 |
|---|---|---|
| 前端（Nginx） | http://localhost:8102 | 业务入口，反代 `/api` 到后端 |
| 后端（直连） | http://localhost:7102/api/health | 调试/健康检查用 |
| MySQL / Redis | 容器网络内部 | 不暴露宿主机端口 |

首次启动自动建表（`db/init/01_schema.sql`）并由后端注入演示数据（`SEED_DEMO=true`，仅当库为空时注入，幂等）。停止并清空数据：`docker compose down -v`。

## 运输排班

- **周/日甘特**：车辆、驾驶员、押运员三组泳道切换；今日列高亮、当前时刻红线、车辆不可用（抛锚/保养）与人员请假斜纹段。桌面为完整甘特，平板（641–1023）甘特+冲突两栏，手机（≤640）自动切换为按日竖向卡片。
- **冲突逐条标红**：同一车辆同段被两单占、同一驾驶员/押运员同时落两单、驾驶证/危货从业资格证/押运证过期或缺失、车辆道路运输证过期、车辆维修时段与人员请假时段。每条冲突在右侧面板单列一行，**展开可看完整中文原因（含重叠时段/时长/关联运单）**，可定位甘特、进运单详情或直接去改派——不是笼统弹窗报错。
- **拖拽排班**：指针事件统一鼠标/触摸，15 分钟自动对齐，跨泳道拖放即换车/换人。落点晚于原计划到达时**强制二次确认勾选并填写原因**，写入 `schedule_adjustments` 留痕。
- **改派与链式重排**：车抛锚/人请假时从当前单解绑重派；同车（及同驾驶员/押运员）后续已派车单按 30 分钟周转间隔**只后移、不提前**链式顺延。先后关系按原始时刻固定（边恒由早指向晚），**结构上无环形依赖**；**运输中/已完成单全程锁定**，目标落点压上锁单直接拒绝。
- **三种空/错文案各不相同**：加载失败=错误态+重试；窗口内无任务但有异常中止单="本排班已全部取消（N 单异常中止）"；无任务有待审核单="N 单还在填报/审核/核验中"；真正无单="该窗口暂无排班"；单条泳道还有"该车/该驾驶员/该押运员本周暂无排班"。
- **车辆利用率口径（已拍板，三处咬死一致）**：采用**时间口径**
  `利用率 = 已排班任务时长并集 ÷（窗口时长 − 车辆登记不可用时长）`，
  已排班取已派车/运输中/已完成运单占用时段（同车重叠只计一次），维修中车辆整窗计为不可用。**不采用**「已执行单数÷派单数」——临时改派多的月份该单数口径只降不升、与真实忙闲反向。口径定义由后端 `UTIL_METRIC` 单点输出，**作战台卡片、排班详情（含车辆明细表）、CSV 导出三处共用同一接口数值与文案**，超排车辆（>100%）红色提示。

## 电子运单状态机

```
填报 ──提交自审──▶ 企业自审 ──自审通过──▶ 监管核验 ──核验通过·派车──▶ 已派车 ──启运──▶ 运输中 ──到达签收──▶ 已完成
 ▲◀──退回修改────┘ ▲◀──监管退回────┘                                  │
 └──────────────────────────── 异常中止（任意未完结状态，须填原因）◀────┘
```

- **非法流转拦截**：回退、跳级、终态变更一律 `409`，返回中文原因与当前合法动作；越角色 `403`、越企业 `403`。
- **人员绑定**：一张运单必须绑定一名驾驶员 + 一名押运员，不得为同一人，且必须属于本企业（创建与提交时双重校验）。
- **运单号**：`企业前缀 + 年份 + 6位顺序号`（如 `AL2026000001`），由 `waybill_counters` 表按企业+年份行锁分配，**只增不减**；异常中止/作废的单号留痕于 `waybills` + `waybill_events`，绝不复用。
- **全程留痕**：每次流转写入 `waybill_events`（操作者、原因、服务端时间、离线端真实发生时间）。

## 离线容错（山区无网场景）

- **离线提示**：断网时顶部横幅常驻提示"当前离线"，列表/详情回退本地缓存并显示**缓存时间与"可能已过期"警示**——不会拿旧单状态冒充最新状态。
- **离线暂存**：驾驶员断网时仍可点击「启运 / 到达签收」，操作进入本机队列（localStorage），记录真实发生时间。
- **幂等合并**：恢复网络后自动重放，重放沿用首次生成的 `Idempotency-Key`；服务端以幂等键表 + 唯一索引去重，重复提交/双击/重试均返回首次结果，**不产生重复运单与重复事件**；同一执行者的同一动作已生效时按"幂等去重"成功返回。

## 企业数据隔离

- 监管员可见全省；企业管理员仅本企业；驾驶员/押运员仅本人绑定运单。
- 越权访问返回结构化错误（`403 FORBIDDEN_ENTERPRISE` 等），前端展示**错误态页面**（🔒 无权访问），不给空白页。

## 运单作战台

- 各企业**待派车漏斗**（填报中→自审中→待核验→已派车待发车）；
- **今日应离 / 今日应到**（计划 vs 实际，超时标记）；
- **异常红点**：今日异常中止、发车超时、到达超时（脉冲红点 + 计数徽标）；
- 响应式断点：≥1440 三列 / ~1024 两列+图标侧栏 / ≤640（390 目标）单列+底部导航+大按钮；
- 聚合结果 Redis 缓存 15s，运单变更即失效。

## API 摘要

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/login` | 登录（JWT） |
| GET | `/api/dashboard/summary` | 作战台聚合（监管员/企业管理员） |
| GET/POST | `/api/waybills` | 运单列表（按角色隔离）/ 填报（需幂等键） |
| GET | `/api/waybills/:id` | 详情 + 留痕 + 当前可执行动作 |
| POST | `/api/waybills/:id/transition` | 状态流转（需幂等键，状态机拦截非法流转） |
| GET | `/api/meta/enums` `/api/meta/crew` `/api/meta/enterprises` | 枚举 / 企业人员 / 企业列表 |
| GET | `/api/scheduling/board?view=week\|day&date=&enterprise_id=` | 排班甘特数据（泳道/任务/逐条冲突/时间口径利用率） |
| POST | `/api/scheduling/check` | 改派预检：链式顺延预览、残余冲突、是否超时到达（不落库） |
| POST | `/api/scheduling/waybills/:id/reassign` | 确认改派+链式重排（幂等键、原因强制、超时确认、逐单留痕） |
| GET | `/api/scheduling/export.csv` | 排班导出（冲突明细+与页面完全同口径的利用率） |

写操作必须携带 `Idempotency-Key` 请求头（前端自动生成，离线队列重放时沿用）。

## 本地开发（不用 Docker）

```bash
# 依赖：本机 MySQL 8（建库 anyuntong，导入 db/init/01_schema.sql）与 Redis
cd backend && npm install && npm run dev        # 后端 :7102，首启自动注入演示数据
cd frontend && npm install && npm run dev       # 前端 :5173，/api 代理到 7102
cd backend && npm test                          # 状态机/校验器单元测试
```
